# SPEC.md — reporte-simple

Reporte de solo lectura de **Conexiones** y sus **Vuelos**, tomado del servicio RAP `ZMAKS_SB_CONEXIONES` en S/4HANA on‑premise (cliente <S4_CLIENTE>).

Cada regla tiene un test automático en `test/`, salvo las marcadas `[manual]`, cuyos pasos están en `test/PRUEBAS_MANUALES.md`.

## Análisis del servicio origen

Se completa al inicio de cada reporte, revisando el `$metadata` / el `.cds` importado.

| Pregunta | Resultado para `ZMAKS_SB_CONEXIONES` |
|---|---|
| ¿Trae anotaciones `@UI` (LineItem, SelectionFields, Facets, HeaderInfo)? | ⚠️ Sí, completas, pero **no utilizables tal cual**: el RAP declara el vocabulario UI con el alias `SAP__UI` y `cds import` copia `$Type: 'SAP__UI.DataField'` / `'SAP__UI.ReferenceFacet'` (34 registros). CAP publica el vocabulario con el alias `UI`, así que Fiori descarta esos registros (tabla sin columnas, detalle vacío) y los `Target` de los facets salen como `Path` en vez de `AnnotationPath`. Solo `SelectionFields` y los `DataPoint` (sin `$Type`) funcionan. Se redefinen en `app/conexiones/annotations.cds` (D22) |
| ¿Trae etiquetas (`@Common.Label`) y textos (`@Common.Text`)? | ✅ Sí (`CarrierId` → `CarrierId_Text`) |
| ¿Soporta agregación (`$apply`)? | ⚠️ Parcial. Declara `aggregate`, `groupby`, `filter` (sin `concat`). **Probado en el RAP real** (usuario, 2026-11-10, `/IWFND/GW_CLIENT`): `aggregate(SeatsOccupied with sum as TotalOcupados)` → OK (9161); `aggregate(SeatsOccupied with sum as SeatsOccupied)` → **error** "Property name 'SeatsOccupied' is already used" (el alias no puede llamarse igual que el campo); `aggregate(SeatsOccupied)` → error "not flagged as custom aggregate" hasta agregar `@Aggregation.default: #SUM` en el RAP (D45), después OK; `concat(...)` → **error** "No implementado" (`/IWBEP/CM_V4S_RUN/002`): este Gateway no soporta `concat`; `Conexiones(…)/_Flight?$apply=aggregate(SeatsMax)` → OK (520). **Peticiones de la tabla analítica de Fiori, probadas en el RAP real** (usuario, 2026-11-10, AA 0015): (A) `aggregate(SeatsMax,SeatsOccupied)` → OK; (B) `groupby(...)/aggregate($count as UI5__count)` → **error**; (C) `groupby(...)/top(109)` → **error** "Unsupported transformation 'top'". **Conclusión:** este Gateway solo soporta `aggregate`, `groupby` y `filter`; la `AnalyticalTable` de Fiori V4 necesita además `concat`, `top` y `$count` → no se puede usar contra este RAP; totales en la cabecera del detalle (R14, D47). CAP no delega `$apply` (D43) |
| ¿Tiene parámetros CDS (vistas con `parameters`)? | ❌ No |
| ¿Tiene campos de importe / unidad (`ISOCurrency`, `IsUnit`)? | ✅ `Price` → `CurrencyCode`; `DistanceUnit` es unidad |
| ¿Los decimales conservan su escala tras `cds import`? | ⚠️ No: `Price` es `Edm.Decimal` `Precision="16" Scale="variable"` (importe ABAP, los decimales dependen de la moneda), pero `cds import` lo deja como `Decimal(precision: 16)` (escala 0 en CDS) y CAP publica `Precision="16"` sin `Scale` → Fiori muestra 423 USD en vez de 422.94. Se corrige en `srv/service.cds` (R12, D31, D32). Es el único `Edm.Decimal`; `Distance`, `SeatsMax` y `SeatsOccupied` son `Edm.Int32` y las horas `Edm.TimeOfDay` |
| ¿Los value helps (`ValueListReferences`) apuntan a servicios disponibles en CAP? | ⚠️ No: apuntan al servicio F4 `/dmo/i_airport_stdvh` (`/srvd_f4/...`), que CAP no trae. Su `$metadata` referencia al servicio padre con el alias `SAP__ParentService` y `cds import` falla ("Could not resolve the schema SAP__ParentService…") → se importa una copia sin esa referencia (D49). **Probado en el RAP real** (usuario, 2026-11-10, `/IWFND/GW_CLIENT`): `.../srvd_f4/dmo/i_airport_stdvh/0001/xDMOxI_Airport_StdVH` → **error**; con los parámetros de matriz `;ps='srvd-zmaks_sd_conexiones-0001';va='…airportfromid'` → **OK**, devuelve aeropuertos (D51). `$search` sobre el F4: **no probado** (el F4 declara `SearchRestrictions.Searchable`, sin frases). Value help resuelto en CAP con `@Common.ValueList` sobre `Aeropuertos` (D50) |
| ¿Hay restricciones de filtro? | `Vuelos.Price`: solo `MultiValue` |
| ¿Las asociaciones traen su condición (`on`)? | ⚠️ No: el `$metadata` de OData V4 no publica condiciones, y `cds import` deja `_Flight : Association to many Vuelos { }`. **Condición real, confirmada en ADT** (2026-11-10, `ZMAKS_I_CONEXIONES`): `association [1..*] to ZMAKS_I_VUELOS as _Flight on $projection.CarrierId = _Flight.CarrierId and $projection.ConnectionId = _Flight.ConnectionId`. En producción la resuelve el RAP (D26); solo el mock la necesita y la usa tal cual (D25). Aunque el RAP declare `[1..*]`, una conexión sin vuelos se muestra con la tabla vacía (R7, D28) |

## Semántica del reporte

Fuente de verdad para las anotaciones del reporte. Columna **Origen**: `RAP` = viene del servicio; `CAP` = se define o sobrescribe en `app/conexiones/annotations.cds`. Cambiar esta tabla primero; luego las anotaciones; luego el test R11.

> **Columnas, secciones y cabecera = `CAP` (D22):** el RAP las trae con el alias `SAP__UI`, que CAP no reconoce. Etiquetas y orden se toman del RAP, pero se definen en `annotations.cds`. La columna **Origen** de las tablas de abajo se refiere a la etiqueta, el filtro, el texto y la unidad del campo; las columnas (`UI.LineItem`) son siempre `CAP`. La columna **Etiqueta** es a la vez la etiqueta de la columna (`UI.DataField.Label`) y la del campo (`@Common.Label`, la que usan el selector de columnas, los filtros y los value helps) (D24). **Encabezado** = `@Common.Heading` y **Ayuda** = `@Common.QuickInfo` (tooltip), en español (D40). La tabla incluye **todos** los campos de cada entidad, también los que no son columna, para que ningún texto en inglés del RAP quede sin traducir; R11 lo verifica. En **Medida**, `_SUM_` = agregado predefinido `SUM` (`CustomAggregate` + `@Aggregation.default: #SUM`, igual que el RAP, D45), necesario para que CAP entienda `aggregate(Campo)` en las lecturas con `$apply` (D43). Desde D47 **no hay total al pie de columna** (sin `@Analytics.Measure` ni `ApplySupported`: este Gateway no soporta la tabla analítica). Los totales de R14 son campos `virtual` de `Conexiones` que se muestran en la cabecera del detalle y calcula el handler (D47).

## Lecciones aprendidas (MCP)

- **L1 — El agente se saltó los guardrails del MCP leyendo el CSV directamente** (MCP Nivel 3, prueba del agente, 2026-11-17). En el primer intento de la prueba 3 (ocupación de `AA 0017`), la tool MCP `query` falló por el revisor de permisos de Claude Code, y el agente, para responder igual, leyó `test/data/ZMAKS_SB_CONEXIONES-Vuelos.csv` con sus herramientas de archivos. Así esquivó todo lo que protege `ReporteAgentService`: `@requires: 'Visualizador'`, `@readonly`, el límite 50/200, los campos de D70 y la delegación al RAP (R4). En el segundo intento respondió por MCP (96,6 % y 52,2 %, con la fórmula de la descripción de `Vuelos`). **Conclusión para el Nivel 7:** en producción el agente debe tener **solo las tools MCP**, sin acceso a archivos ni a la terminal; los guardrails de CAP solo valen si el MCP es el único camino a los datos. En desarrollo, una respuesta del agente cuenta como prueba de R15 solo si salió de `query`/`describe` (revisar las tools usadas).
